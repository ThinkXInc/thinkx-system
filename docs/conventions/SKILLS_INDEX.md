## フロントエンド(画面)

- **[共通] 新しい画面を作る — 画面描画の全体フロー**
  レンダー HTML(言語・ロケール・リダイレクト URL の注入)→ `DOMContentLoaded` で最親 View 初期化 →
  サブビュー初期化 → DOM エレメント生成、の流れ。
- **[共通] View クラスの三部構成を書く** — 画面の初期化 / イベントのハンドリング / ヘルパー関数。
- **[共通] `createElements` などメソッド名の慣習に合わせる** — 頻出メソッド名をサンプルから学ぶ。
- **[共通] DOM 要素を `$` 接頭辞の変数で扱う。**
- **[共通] カスタムイベントで親へ委譲する** — View 内で扱えないイベントを親側で拾って通信する。
- **[共通] HTML へ情報を注入する** — 言語識別子・ロケール辞書・リダイレクト URL。ユーザ紐付き情報は
  画面初期化時に API で取得する。
- **[共通] ロケールキー/定数のハードコーディングを判断する** — 1 度しか使わないキーはハードコード可。
- **[共通] 共通ライブラリへ切り出すかを判断する** — 他アプリでも使い、行数を要する一般処理は共通化。
- **[共通] 画像・アイコンを SVG で用意する。**
- **[共通] エラーページ(404 / 500)を用意する** — アプリごと独立(共通化しない)。

## よく使うコンポーネント(手順)

- **[共通] `PageView` で View をページ分類する。**
- **[共通] `TextField` で入力フォームを作る** — 変更追跡・バリデーション・カウンタ・アラート表示。
  拡張は「フレームワーク基底+1段」の範囲(AXIOMS の継承規約に従う)。
- **[共通] `PageView` のページをファイル分割するか判断する** — 各画面の行数で決める。

## クライアント側の通信ハンドリング

- **[契約] エラーレスポンスの 3 パターンをハンドリングする** — 成功 / 単体エラー / 複数バリデーション
  エラー。分割代入で `errors` の有無を判別し、メッセージを `TextField` か画面メッセージへ渡す。
  (外形の契約は libcommon L-7 / PROTOCOL.md。)
- **[共通] 401 / 403 を受けたらログイン画面へリダイレクトする。**

## サーバサイド(Python)

- **[契約] セッションを開始/クリアする** — `str(user.id)` を渡してセッション開始、クリアで Redis から
  削除。デコレータでセッション検証。(実装 API は libcommon L-7。cookie 名等はリポ固有。)
- **[共通] 返却値は共通フォーマッタで作る** — Flask は HTTP レスポンスフォーマッタ、Celery タスクは
  `success` キー+データ。(フォーマット族の契約は L-7。)

## スタイル

- **[リポ] スタイルシートを配置する** — ベース/リセットは共通ライブラリ、汎用コンポーネントは共通側、
  画面固有は識別子でグルーピングしたアプリのスタイルファイル。(パスはリポ固有。)
