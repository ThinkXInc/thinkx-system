## Claude

理解は逆で、gitignore したファイルは変更されても検出されない。「無視するが変更は見張る」という中間状態は git に存在しない。

ただし**オーナー案(gitignore する)のほうが優れている**。`--untracked-files=no` は untracked を一括で見なくするため、サーバー上で新規作成された未知のファイルも黙って通す。gitignore は列挙したパターンだけを無視する許可リスト方式で、列挙外の新規ファイルは今まで通り検出される。推奨を撤回してオーナー案を採用。

副作用としてスクリプトの変更が不要になった(`git status --porcelain` の厳格判定のまま)。`.gitignore` に `get-pip.py` / `*.swp` / `*~` を追加。なぜ `--untracked-files=no` を選ばなかったかもコメントに残した。

## この実装フェーズで守るべきだと分かったこと

- **名前は重要なもの(操作対象)を先に置く**(`docs/GUIDELINES.md` に記録済み)
- **サービスごとにスクリプトを増やさない。** 引数で受ける
- **同じ処理を2箇所に置かない。** 手動と自動で実装が分かれていたためビルド漏れを両方に当てる羽目になった
- **貼り付け用コマンドは折り返す長さにしない**
- **エラーは「次に打つ1行」を出す**
- **ユーザーが名前を覚える必要のないものを、入口として並べて見せない**
- **推論で役割を決めない。** `curl localhost:80` が 000 だっただけで「nginx は動いていない」と判断して誤った
