> **KOBITOのリモコンインターフェースに「Claudeをアップデート」ボタンを追加した方がいいだろう　claude updateを書き込む操作は忘れるし覚えられない　右下の空白箇所に置いて押すと今いくつでいくつになるか->実行**

server.py に GET /connect/update(今の版 = `claude --version`・最新版 = `npm view`、何も変えない)と
POST /connect/update(deploy と同型の裏実行・202 + state.update)を追加。update 後に版が取れなければ
install.cjs を自動実行して復旧(同日朝の GUIDELINES の手順)。本番入口の中継許可リストに update を追加
(固定 5 パス)。画面は右下にカード+黒ボタンで実装し、ローカルのモック+Chrome 実測で
版提示→実行→進行→完了を確認してスクショ提示。文言指示(見出し「Claudeをアップデート」・ボタン「更新」・
説明文なし)を反映後、OK が出て commit したところで —

> **いやちょっと待て**

> **アップデートはそれほど重要でないから　他のボタンと同等であるのは微妙**

カードをやめ右下フッター並みの小さなテキストリンクに格下げした案を提示。

> **それは目立たなさすぎる**

中間(白地+枠の quiet ボタンを右下=本番への反映の右隣・下端揃えに置く)に変更。

> **実行　やめる　も控えめなボタンにしろ**

実行/やめるも同じ quiet ボタンに。モック OK →「OK」で commit・push した直後 —

> **ちょっと待て**

> **(モックの完了表示を見て)どうやって作り直す？サーバーを再起動？だとしたら Claudeをアップデートボタンはそれが実行されるようになるべきでは　というかサーバーを落としたりするボタンが今ないのはなぜ**

整理: 作り直し = EC2 再起動ではなく tmux 内の claude の作り直し。ただし現画面には正常稼働中の
セッションを作り直す手段が無い(「セッションを再接続」は壊れているときだけ作り直す)。
EC2 の停止/起動は本番入口の電源カードに既にある。選択肢(A 完了後に作り直しボタン /
B 実行で作り直しまで一気 / C 作り直しボタン常設)を提示。

> **確かに今のセッションが消されるのはまずい　だとしたらstagingを停止ボタンを押して再起動する操作になるのか？普通はそう考えるが　迷う人のために　Claudeをアップデートを stagingを停止　に変えるべきでは　それならセッションが切れることを示唆している**

はい — 停止→起動で boot の claude-session が新しい claude を立ち上げるので反映される(同日朝の
unit PATH 修正で boot 起動も正常)。解釈が 2 通りあるため確認(停止に統合 / 更新後に停止を出す / 案内だけ)
→ **オーナー選択: 更新後に停止を出す**。完了時にその場へ「staging を停止」quiet ボタンを出し、
押すと電源カードの停止と同一の操作が走る実装に(電源 API が無い staging 直開きでは文言のみ)。

> **staging起動ボタンしかでないが**

実測でモックを停止状態まで進めたのが残っていた(モックは状態をプロセス内に持つ)。再起動でリセット。

> **最後のClaudeをアップデートはこの段階でいらないだろ　直後は　stagingを停止だけでいいよ**

完了直後は「staging を停止」だけを出し、更新ボタンは引っ込める(停止を押したら通常表示に戻す)。

> **staging を停止→起動すると反映されます**

完了文言を「〜すると新版になります」から「〜すると反映されます」へ変更。

> **モックの挙動はよさそうなのでこれで**

staging へ反映(develop マージ → deploy_staging → claude_connect 再起動)。実測:
/connect/update = {current 2.1.283, latest 2.1.283, same:true}・画面に update_check/update_stop あり・
tmux セッションは KillMode=process により生存。

> **本番に反映して記録してセッションを終える**(→ **続けて**)

再開時(10-01)に確認したところ、本番へは release/2026-09-30(PR #146)として反映済みだった
(production..develop の差ゼロ・e49e0b7 を production が含む・prod checkout に update_check と
中継許可 update:30・トップ 200・/remote_control/ は Basic 認証ガード作動)。
