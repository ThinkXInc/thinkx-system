# デプロイ手順書

ローカルで編集 → staging で確認 → 本番へ。順に叩く。

## 通常フロー

0 staging -> PR -> monorepo (remote)
```
cd ~/Sources/thinkx-system
bash infra/scripts/pr_develop_and_merge_to_monorepo.sh
```

1 local (working tree) -> local (monorepo branch) -> origin

出すものを見る
```
cd ~/Sources/thinkx-system
git status --short
```

サイトの変更を確定して上げる(コミットの粒度は編集したディレクトリ単位)
```
cd ~/Sources/thinkx-system
git add thinkx/
git commit -m "text(thinkx): サイトの変更"
git push origin monorepo
```

infra の変更を確定して上げる
```
cd ~/Sources/thinkx-system
git add infra/
git commit -m "fix(infra): 手順・スクリプトの変更"
git push origin monorepo
```

出すのは origin に在るものだけである。commit も push もしていない変更は、以降の
手順が全部緑で完走しても staging には出ない(2 は `origin/monorepo` しか見ない)。
`git add -A` は使わない — 他トラックの WIP を巻き込む(D-68)。ディレクトリ単位で
add するのは、自分が触った範囲だけを確定するためである。message は後から
`git commit --amend -m` で直せる。

2 local (monorepo branch) -> PR -> develop
```
cd ~/Sources/thinkx-system
bash infra/scripts/pr_and_merge_to_develop.sh monorepo
```

3 develop -> staging (web + LB。assets も自動で配る)
```
cd ~/Sources/thinkx-system
bash infra/scripts/deploy_staging.sh
```

staging を確認する
```
https://staging.thinkxinc.com
https://staging.truetechjapan.com
https://staging.transformism.art
https://staging.kazukiotsuka.com
```

4 staging -> production (このコマンドの実行 = 承認)
```
cd ~/Sources/thinkx-system
bash infra/scripts/deploy_production_from_staging.sh
```

## 他セッションが編集中でも 0 / 2 は安全(D-68)

実体の merge はリモート(GitHub の PR)で行い、手元は ff でポインタを進めるだけ(commit を作らない)。
だから他トラックの編集中(未コミット)を巻き込まない。**やってはいけないこと**:
- 手元で `git merge origin/develop`(非 ff・merge commit がツリー全体を固める)
- `git stash` で他トラックの WIP を退避する
- `git add -A`(自分のパスだけ commit する)

## 戻し方(前の release に戻す)

release 一覧を見る
```
cd ~/Sources/thinkx-system
git fetch origin
git branch -a --list 'origin/release/*'
```

戻したい release を選ぶ(上の一覧から1つ。この行だけ日付を書き換えて貼る)
```
cd ~/Sources/thinkx-system
BACK_TO=release/2026-08-06
```

その release を production に入れ直して反映(production を直接巻き戻さない)
```
cd ~/Sources/thinkx-system
gh pr create --base production --head "$BACK_TO" --title "rollback to $BACK_TO" --body ""
gh pr merge --merge --delete-branch=false
bash infra/scripts/deploy_production_from_staging.sh
```

## 同期が止まったとき

deploy_staging / deploy_production は何も消さずに止まる。

| 表示 | 意味 | 対処 |
|---|---|---|
| `WRONG-BRANCH` | サーバーが対応 branch に居ない | 表示された `checkout -B` を実行して再実行 |
| `DIRTY` | 未コミットの変更がある | commit・push して取り込む。不要なら破棄。きれいにして再実行 |
| `NON-FF` | 対象 branch に無いコミットがある | push して取り込み、早送り可能にして再実行 |

## 原則

- 承認 = 確認した ref から release を切る。承認してから後で切らない。
- 全サービスを足並み揃えて出す。選んで出す仕組みは持っていない。
- staging へ出るのは常に origin/develop。手元の作業ツリーや branch からは出さない(D-58)。
- サーバーは reset で無言上書きしない。明示 ref へ ff-only、消せない変更があれば止める。
- 取りうる値が1つしかないものは、引数にも名前にも書かない(deploy_staging は引数なし)。
