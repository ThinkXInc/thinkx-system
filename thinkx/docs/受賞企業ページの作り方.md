# 受賞企業ページの作り方(truetechjapan / Best Technology Startup 100)

対象: `truetechjapan.com/award/<企業キー>` に1社分のページを追加する作業。
初版 2026-07-20。ThinkX / Augmented Communications / レボーン / BEAM Technologies の
4社を実際に作った過程から起こした。

**この作業の要点は「テンプレートを触らずに JSON を1枚足すだけで1社増える」こと。**
レイアウトを変えたくなった時だけ HTML / LESS に触る。

---

## 2. 1社追加する手順

### 2-1. 企業キーを決める

**ID は振らない。企業キーがそのまま URL になる。**

```
truetechjapan.com/award/thinkx
truetechjapan.com/award/augmented-communications
```

キーは `main.py` の `AWARD_COMPANY_KEY_PATTERN` = `^[a-z0-9][a-z0-9_-]*$` を満たすこと
(小文字英数字とハイフン・アンダースコア)。ファイル名 = キー。

### 2-2. ロゴを置く

`web-server/views/img/truetechjapan/award_companies/<キー>.(png|svg)`

`cp` は settings で禁止されているので python でコピーする。

```bash
cd thinkx/web-server/views/img/truetechjapan/award_companies
python3 -c "import shutil; shutil.copyfile('<元>', '<キー>.png')"
```

### 2-3. JSON を書く

`web-server/views/templates/truetechjapan/award_companies/<キー>.json`。
スキーマは 3 章。

### 2-4. sitemap に追記する

`web-server/sitemap_truetechjapan.xml` の AWARD セクションに1エントリ足す。既存の
他社エントリをコピーしてキーを置換するだけ。**これを忘れると検索エンジンや SNS の
クローラーがそのページを発見できない**(実際 4社とも抜けていて 2026-07-22 に追加した)。

ja/en の `xhtml:link rel="alternate"` 付き・`changefreq monthly`・`priority 0.7` で
既存 award エントリに揃える。sitemap は手書き運用(自動生成しない)。

### 2-5. og:image を生成する

SNS シェア時のカード画像(1200x630 PNG)を生成する。ロゴ・会社名・認定シール・tier を
テンプレ JSON から自動で構成するので、**JSON とロゴさえ正しければ手作業は無い**。

```bash
cd thinkx/web-server
./venv/bin/python generate_award_ogp.py --font <和文フォント(ttf/otf)のパス>
```

`--keys <キー>` で1社だけ生成もできる。生成先は
`views/img/truetechjapan/award_companies/ogp/<キー>.png`。

依存(Pillow / svglib / PyMuPDF)は本番 requirements に入れない開発時ツール。venv に
無ければ個別導入する(pytest と同じ扱い・§8-5)。和文フォントは Noto Sans JP 等を
`--font` で渡す(この環境には和文フォントが無いので curl 等で用意する)。
`ogp/*.png` は `.gitignore` 対象外なのでコミットして本番へ運ぶ。

> ロゴが SVG(revorn 等・`<style>` で色指定)のときは、スクリプトが CSS 色を fill 属性へ
> 展開してから PyMuPDF でラスタライズする。素のままだと PyMuPDF は CSS を解釈せず
> 色が黒に落ちる(4-2 の既知の罠)。

### 2-6. CSS をビルドする(スタイルを変えた時だけ)

```bash
cd thinkx/web-server/views
node_modules/.bin/lessc src/less/main.less css/main.css
```

`css/main.css` は `.gitignore` 済み(ビルド生成物)なのでコミットしない。
JSON を足すだけならこの手順は不要。

> 未検証: 本番デプロイ(`deploy.sh` → ansible playbooks)のどこで CSS がビルドされるかは
> playbooks が別リポジトリの submodule で未初期化のため確認できていない。
> 初回デプロイ時に本番の `main.css` に新スタイルが入っているか確認すること。

### 2-7. テストを通す

```bash
cd thinkx/web-server
./venv/bin/python -m pytest tests -q
```

`award_companies/` に JSON を1枚足すと、その企業は
`test_award_company.py` の対象に**自動で入る**(ja/en 両方でレンダリングされ、
JSON の各値がページに出ているか照合される)。ルートを増やしていないので
`tests/golden/route_sweep.json` は触らなくてよい。

### 2-8. 見た目を確認する

4章の検証ハーネスを使う。SNS カードは公式デバッガが staging(Basic 認証)を読めない
ため、本番反映後に確認する(または生成済み `ogp/<キー>.png` を目視)。

**SNS カードのデバッガ**: X(Twitter)の cards-dev validator は廃止済みで使えない
(2026-07-22 実地)。Facebook の Sharing Debugger(`developers.facebook.com/tools/debug/`)
に本番 URL を入れ、初回は "Scrape Again" でキャッシュを更新する。og:* は X/Facebook で
共通なのでこれで足りる。本番(`truetechjapan.com`)は Basic 認証が無いのでデバッガが読める。

## 3. JSON スキーマ

```json
{
  "company_name": { "ja": "ThinkX株式会社", "en": "ThinkX Inc." },
  "url": "https://thinkxinc.com",
  "tier": "Top-Tier",
  "award_year": 2026,
  "founders": { "ja": ["大塚一輝"], "en": ["Kazuki Otsuka"] },
  "logo": {
    "src": "/img/truetechjapan/award_companies/thinkx.png",
    "format": "png",
    "alignment": "center"
  },
  "business": { "ja": "…", "en": "…" },
  "award_reasons": { "ja": ["…", "…"], "en": ["…", "…"] },
  "interview_url": null
}
```

### 多言語フィールド

`company_name` / `founders` / `business` / `award_reasons` は `{ja, en}` で持つ。
`main.localize_award_company()` が言語で潰す。

**訳が未供給(キーが無い・空配列・空文字)なら ja にフォールバックする。**
英訳が届いていなくてもページは落ちず、`/en` に日本語が出る。
英訳が届いたら `en` を埋めるだけでよい。

`tier` / `url` / `award_year` / `logo` は言語に依らないので単一値。

### 任意フィールド

| フィールド | null / 未設定のときの挙動 |
|---|---|
| `tier` | ティアチップと「トップティア枠」ラベルを**節ごと出さない** |
| `interview_url` | インタビュー節を**節ごと出さない** |
| `logo.background` | 地色なし。`"dark"` を指定すると暗パネルの上にロゴを置く(4-3 参照) |

### 新しいティアを増やすとき

チップの文字は `tier` の値をそのまま出す。その下の日本語ラベルは
`locales/truetechjapan/award_company.json` の `award_tier_note` を引く。

```json
"award_tier_note": {
  "ja": { "Top-Tier": "トップティア枠" },
  "en": { "Top-Tier": "Top-Tier Category" }
}
```

ここに無いティアはチップだけ出てラベルは出ない(壊れない)。新ティアを作ったら
このマップに足す。

## 4. ロゴの扱い

### 4-1. サイズ

CSS 側で `max-width: 320px / max-height: 160px`(スマホは 200x110)に収めるので、
元画像の寸法は問わない。透過 PNG か SVG が望ましい。

### 4-2. SVG はそのまま置いてよい

レボーンの `revorn.svg` は `<style>` ブロックで色を指定しているが、ブラウザは
CSS を解釈するので正しく出る。
(注: PyMuPDF で SVG をプレビューすると色が落ちて黒く出る。ブラウザで確認すること。)

### 4-3. 白抜きロゴしか無いとき

本ページの地は白なので、白抜きロゴはそのままでは**見えない**。

**他社ロゴの色を勝手に反転しないこと。** ロゴは無加工のまま、暗パネルに載せる。

```json
"logo": {
  "src": "/img/truetechjapan/award_companies/beam-technologies.png",
  "format": "png",
  "alignment": "center",
  "background": "dark"
}
```

これは暫定対応である。**正式なロゴデータを企業から受領するのが本筋。**

## 5. URL とルーティング

`main.py` のルート:

```
/truetechjapan/award/<company_key>
/truetechjapan/<lang>/award/<company_key>
```

nginx(`loadbalancer` ではなく `thinkx/web-server/nginx/conf.d/thinkx.conf` の
truetechjapan.com サーバブロック)が

```
rewrite ^/(?!truetechjapan)(.*)$ /truetechjapan/$1 last;
```

を持つので、公開 URL は `/truetechjapan` の付かない形になる。

| 公開 URL | 内部パス |
|---|---|
| `truetechjapan.com/award/thinkx` | `/truetechjapan/award/thinkx` |
| `truetechjapan.com/ja/award/thinkx` | `/truetechjapan/ja/award/thinkx` |

未登録キー・不正キーは 404(`load_award_company()` が None を返し `abort(404)`)。

## 6. レイアウト(PDF との対応)

典拠は配布用 PDF。**PDF の斜線ボックスとピンク文字は企業への記入指示であり、
サイトには出さない。**

PDF から 300dpi でサンプリングした実測値:

| 要素 | 高さ | 角 | 背景 | 文字 |
|---|---|---|---|---|
| 受賞年 / 創業者ラベル | 30.5pt | 直角 | 単色 `#f0d484` | 黒・`font-weight: 600` |
| Top-Tier チップ | 12.5pt(ラベルの約 0.41 倍) | 角丸 | グラデーション | 金茶 `#b38e0c` |

**この2つは別物。** 同じ黄色い箱に見えるが、高さも角も文字色も違う。

### PC とスマホの違い

| | PC | スマホ(710px 以下) |
|---|---|---|
| 社名とティア+シール | 左に社名、右にティア+シール | **左にシール+ティア、右に社名** |
| ティアとシールの並び | 横並び(ティアが左) | **縦積み(シールが上)** |
| 社名の縦位置 | 上揃え | 左ボックスの高さの**中央** |

スマホの社名は 6〜7 割の幅で、長ければ折り返す
(`min-width: 0` + `overflow-wrap: anywhere`)。

ティアの無い企業は左ボックスが低くなるぶん、相対的に社名の位置が変わる。
**企業ごとの分岐は持たない**(`align-items: center` の1規則で両方を扱う)。

## 7. 見た目の検証(ローカル実描画)

このリポジトリだけでは見た目を確認できないので、検証用ハーネスを別途組む。
スクラッチパッドに置き、プロジェクトは汚さない。

必要なもの:

- **サーバ**: プロジェクト venv(python3.9)で Flask を起動。本番の nginx が配る
  `/css/ /img/ /js/` の alias と、`rewrite ^/(?!truetechjapan)` を WSGI ミドルウェアで再現する。
  **この rewrite が無いと `base.html` の言語判定 JS が先頭セグメント `truetechjapan` を
  言語コードでないと見なしてリダイレクトし、404 になる。**
- **ブラウザ**: playwright + chromium(スクラッチパッド venv)。
  サーバとブラウザで venv が違うので、サーバは別プロセスとして起動し HTTP 越しに撮る。

この環境(EC2)では chromium に必要な共有ライブラリが無く、sudo も使えない。
root 権限なしで deb を展開して解決した:

```bash
apt-get download libgbm1 libdrm2 libdrm-common libwayland-server0
for d in *.deb; do dpkg-deb -x "$d" libs; done
LD_LIBRARY_PATH=$PWD/libs/usr/lib/x86_64-linux-gnu ... python run_shot.py
```

PDF の実測にも同じ venv の PyMuPDF を使う(色のサンプリング、要素寸法の測定)。

## 8. 落とし穴

### 8-1. Mac から届くファイル名は NFD

filedrop 経由で Mac から上がってくる日本語ファイル名は濁点・半濁点が分解されている
(NFD)。シェルに NFC で打った名前は**一致しない**。

```bash
mv Downloads/*.pdf 移動先/          # glob を使う
```

### 8-2. `cp` は禁止

`.claude/settings.json` が `Bash(cp:*)` を deny している。
python の `shutil.copyfile` を使う。

### 8-3. テストで JSON の値をそのまま部分一致させない

Jinja のオートエスケープでアポストロフィが `&#39;` になる。英訳に `'` が入ると
素の値では一致しない。`markupsafe.escape()` で期待値を揃える
(`test_award_company.py` の `_as_rendered()`)。

### 8-4. テスト用 Config はキーを明示列挙している

`tests/config_test.py` は必要なキーだけを持つ。`main.py` で新しい `Config.XXX` を
使うと AttributeError で落ちる。conftest の設計どおり、テスト側にキーを足す
(本番 `config.py` は編集しない)。

### 8-5. pytest は requirements.txt に無い

`requirements.txt` は本番ピン。pytest は入っていないので venv に個別導入する。

## 9. データの受け取り

オーナーは **filedrop**(`/filedrop`、staging 限定)でファイルを上げる。
保存先は `/src/thinkx-system/Downloads/`(gitignore 済み)。

Evernote の `.enex` で届くことがある。1ファイルに複数社の情報とロゴが入っている。
テキストは `<content>` の CDATA、ロゴは `<resource>` の base64。
ロゴと本文の対応は `<en-media hash="...">` の hash = リソースの **MD5** で取る。

```python
import re, base64, hashlib
for r in re.findall(r'<resource>(.*?)</resource>', enex, re.S):
    raw = base64.b64decode(re.sub(r'\s+', '', re.search(r'<data[^>]*>(.*?)</data>', r, re.S).group(1)))
    print(hashlib.md5(raw).hexdigest(), re.search(r'<file-name>(.*?)</file-name>', r).group(1))
```

## 10. 判断の原則(実際に迷った箇所)

- **人名を推測しない。** ローマ字表記が確認できないときは `founders.en` を空にし、
  日本語フォールバックで出す。推測で埋めない。読みが一意でない名前は必ずある
  (例: 俊治 → Shunji / Toshiharu / Toshiji)。
  公式サイトに自称表記があればそれを採る(語順も変えない)。
- **審査の文言を勝手に書き換えない。** 受賞理由と事業内容が食い違って見えたら、
  まず調べる。BEAM の例では、受賞理由の Far-UVC は創業チームの理研での研究実績で、
  現事業(宇宙半導体製造)とは別だった。文言の調整はオーナーの指示を得てから行う。
- **他社のロゴを加工しない。** 4-3 参照。
- **不足している値は null のまま出す。** tier が未供給なら null(チップ非表示)にして、
  埋まった時点で JSON を直す。仮の値を入れない。
