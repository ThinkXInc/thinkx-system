## 用語(オーナー指示による呼び分け)

| 用語 | 意味 |
|---|---|
| **1次編集画面(podcast編集画面)** | 既存の編集画面(`/id?id=<ID>`)。podcast コンテンツのための編集 |
| **切り抜き編集画面(切り抜き作成画面)** | 今回新設する1段深い階層の画面。切り抜き動画のコンテンツのための編集 |
| **動画作成画面** | 切り抜き編集画面からさらに遷移する画面。切り抜きごとの動画設定・生成・書き出し |
| **切り抜きセグメント** | 切り抜き編集画面で S(開始)〜E(終了)で指定された1本の切り抜き区間 |
| **凍結版(クリップ版)** | 切り抜き編集の対象として専用に保持される「確定した音源」のスナップショット。1次編集を後から変えても影響しない |

## 大原則

1. **既存データの完全維持。** 既存の `edit/segments.json` 等には一切書き込まない(唯一の例外:
   既存機構をそのまま使う受信ジャーナル `edit_save_journal.jsonl` への追記。これは追記専用で
   既存行を変更しない)。着手前に C-0 で全編集データをバックアップする(オーナー指示の保険)。
2. **切り抜き編集は1次編集から独立。** 1次編集を後から変更しても、既存の切り抜き編集には
   影響しない。実現方法: 「切り抜きを作成」を押した瞬間の編集状態(区間+drops)を凍結版として
   スナップショットし、以後その凍結版だけを見る(§データ設計)。1次編集が変わると凍結キーが
   変わり、**別の(新しい)切り抜き編集画面**が対応する。対象 podcast コンテンツ1つ(=凍結版
   1つ)に対して切り抜き編集画面1つが対応し、編集データ・履歴もその凍結キーに紐づく。
3. **すべての操作は復元可能な履歴として残す**(podcast 編集と同じ三重の作法:
   localStorage ジャーナル → 受信ジャーナル(fsync) → 履歴退避 + flusher による git commit)。
4. 1項目=1コミット。ブランチは `monorepo`(podcast は 2026refactor トラックではなく
   運用中の monorepo 直)。発見は `podcast/docs/findings.md` へ。パスは明示(D-21)。
5. UI は既存の編集画面の部品・作法(タイムライン・再生・右クリックメニュー・保存表示)を
   踏襲する(オーナー指示「ユーザインターフェースは編集用の既存のものとほとんど近いものになる」)。

## 画面フローの仕様(オーナー指示の構造化)

```
1次編集画面 /id?id=<ID>
  └ 本番使用チェックが付いたセグメントにだけ「切り抜きを作成」ボタンを表示
      └ クリック → その瞬間の編集状態を凍結 → 切り抜き編集画面へ遷移
切り抜き編集画面 /clip?id=<ID>&key=<clipkey>
  機能は「切り抜きセグメントの決定」と「文字起こしテキストの修正」の2つだけに絞る
  └ 画面上部の「動画の作成」ボタン → 動画作成画面へ遷移
動画作成画面 /clip_videos?id=<ID>&key=<clipkey>
  切り抜きセグメントがタイムライン時系列順に並ぶ。各セグメントごとに
  テキスト全文・設定ウインドウ・生成ボタン・再生ウインドウ・書き出しボタン
```

### 切り抜き編集画面の仕様

- タイムラインは**凍結版の編集後音源**(1次編集の drops 適用後)を隙間なく連続表示する。
  時間軸は編集後時間(元音源の時刻から drops 分を差し引いた座標)。文字起こしは既存と同様に
  タイムライン上に重ねる。
- 再生は既存と同じ挙動: Space で再生/停止、右クリックメニューに「ここから再生」。
  再生対象は凍結音源ファイルそのもの(連続音源なのでスキップ処理は不要になる)。
- **S キー** = 現在時刻バーの位置を切り抜きセグメントの**開始**として指定(その時点で分割)。
  **E キー** = **終了**の指定。右クリックメニューからも「ここを開始にする/ここを終了にする」で
  同じ操作ができる。
- 開始〜終了が指定されたタイムラインバーは、開始から終了まで**グラデーション**で色を付ける
  (どこからどこまでが1本かを一目で分かるようにするため)。
- 開始から終了までの間をさらに詰める(セグメント内部の部分カット)ことは**想定しない**(1次編集で
  済んでいる前提)。
- 誤分割の修正: セグメントに含まれない**空白部分を右クリック → 「この間を詰める」**で、
  その空白を挟む前後が結合され1つの切り抜きセグメントとみなされる。
- テキスト修正(字幕の元になるため必須):
  - 文字のまとまり(字幕ユニット)を**クリック → その場で編集**(input に切り替え)。
  - 文字がある場所を**右クリック → 「このテキストを削除」**でそのまとまりを削除。
  - **右クリック → 「ここにテキストを挿入」**でその位置(時刻)にテキストを挿入。
- セグメント決定とテキスト修正は**同時に行える**(一度聞きながら両方やる。聞き直しの往復を
  避けるため)。
- Undo/Redo・自動保存・未保存復元は既存タイムラインと同じ作法。

### 動画作成画面の仕様

- 切り抜きセグメントが**タイムラインの時系列順**に上から並ぶ。
- 各セグメントごとに: テキスト全文 / 設定ウインドウ / **生成ボタン** / 動画再生ウインドウ /
  **書き出しボタン**。
- 生成ボタン → 指定した設定で動画を生成し、再生ウインドウでチェックできる。設定を変えて
  もう一度押すと再生成。
- 書き出しボタン → チェックの入っているサイズ規格すべての動画を書き出しフォルダに出力。
  ファイル名は**タイトル・長さ・サイズ規格**から付ける
  (例: `大学はメディアである_1m23s_1080x1920.mp4`)。
- 動画の構成要素: **音声**(凍結音源の該当区間) + **字幕**(修正済みテキスト。タイミングは
  タイムライン編集で確定済み) + **タイトル**(見出し) + **背景動画**。ロゴ等の常時表示物は
  将来の拡張とし、初期実装には含めない。
- 字幕:
  - フォント: リポジトリ内のフォント置き場(§資産)に置いたフォントファイルから選択できる。
  - サイズ: 数値指定。一般的なドキュメント編集風の +/− と直接入力。
  - 表示位置: 動画ごとに調整せず**システム固定**。リール向けのセオリー(下端ではなく中央寄り・
    大きめ・発話とともに表示)を調査の上デフォルトを決める(§調査)。
  - 部分エフェクト(一部の色変え・一部拡大などの定型強調)は**将来対応**。初期実装しない。
- タイトル:
  - 動画の内容を端的に表す見出し。**動画の最初から最後まで**表示。
  - 基本は上部にシンプルな太字の白。フォント等は動画ごとに変えないか限られたパターンのみ →
    **複数パターンに増やせるようデータ(スタイル定義 JSON)として保存**しておく。
  - 文字数が長くなる可能性があるため、字幕と被らないよう表示領域を分けて確保する。
- 背景動画:
  - 数パターンのテンプレートから選択。実体は**背景置き場フォルダに置いた動画ファイル**で、
    UI はその中から選ぶだけにする(オーナー指示の結論)。
  - 写真数枚からのスライドアニメーション自動生成(位置ずらし+ズームのループ=Ken Burns 風)は
    **任意の後続項目**とする。スクリプトで微妙なものしかできない場合はオーナーがスライド動画を
    自作してフォルダに置く方式で確定(オーナー自身の見立て)。
- 書き出しサイズ規格: リール前提(Instagram / Twitter(X) 投稿)。**縦長と正方形を同時に自動生成**
  できるよう、デフォルトテンプレートを持ち、初期状態で全規格にチェックが入っている(§調査)。

## データ設計

既存の配置規約(idpaths D-025)に従い、新ファイルは idpaths.py に追加定義する。
`<clipkey>` = `<sid>_<hash8>`(sid = 1次編集セグメントの sid、hash8 = 凍結時の
{segStart, segEnd, drops} 正規化 JSON の SHA-256 先頭8桁)。1次編集が変われば hash8 が変わり、
自動的に別の切り抜き編集(別ファイル一式)になる。

```
data/<ID>/
  ├ edit/    (git 追跡 — 人の判断)
  │   clip_<clipkey>_source.json   凍結スナップショット(write-once)。凍結時の区間・drops・
  │                                編集後時間軸に再配置した字幕ユニット(s,e,text)と単語タイム
  │   clip_<clipkey>.json          切り抜き編集の現在状態(セグメント一覧+テキスト修正後ユニット
  │                                +動画設定)。保存のたび全量書き。
  │   clip_<clipkey>_history.jsonl 履歴退避(segments_history.jsonl と同作法・200件)
  │   clip_<clipkey>_journal.jsonl 受信ジャーナル(git 外・端末ローカル。既存 journal と同作法)
  ├ generated/ (git 外・再生成可能)
  │   clip_<clipkey>_source.m4a    凍結音源。source.json の区間+drops を元音源へ適用して生成
  │                                (source.json から決定的に再生成できるため generated 扱い)
  │   clip_<clipkey>_preview_<n>_<WxH>.mp4  生成ボタンのプレビュー動画
  ├ contents/ (git 外・最終成果物)
  │   clip/<clipkey>/<タイトル>_<長さ>_<WxH>.mp4   書き出し
```

- .gitignore 追記: `!data/*/edit/clip_*_history.jsonl` の1行(`clip_*.json` は既存の
  `!data/*/edit/*.json` で既に追跡対象。journal は `.jsonl` 非追跡の既定のまま)。
- 保存経路は既存と完全に同型: 保存 API → 受信ジャーナル(fsync) → 履歴退避 → 全量書き →
  `_queue_for_sync()`(flusher が git commit/push)。ブラウザ側も localStorage ジャーナル+
  3秒再送+未保存復元を同型で持つ。
- サーバー同期: json は git 経由(既存 flusher)。凍結音源・動画は既存の
  `push_assets_podcast.sh`(edit/ 以外全部送る)がそのまま運ぶ。新規機構は作らない。

### 凍結(切り抜きを作成)の動作

1. 1次編集画面で本番使用セグメントの「切り抜きを作成」を押す。
2. サーバーは現在の segments.json から該当 sid の {segStart, segEnd, drops} を読み clipkey を算出。
3. `clip_<clipkey>_source.json` が無ければ作る: transcript.json の単語を drops で間引き、
   編集後時間軸(t' = t − それ以前の drop 合計)へ再配置し、字幕ユニット(間隔 0.8 秒以上または
   句読点で区切った文字のまとまり)にまとめて保存。`clip_<clipkey>.json` も初期状態
   (セグメントなし・ユニット=source のコピー)で作る。
4. 凍結音源 `clip_<clipkey>_source.m4a` をバックグラウンド生成(既存 export_audio.py の区間書き
   出しを流用)。
5. 切り抜き編集画面へ遷移。既に同じ clipkey が存在すればそのまま開く(再凍結しない)。
- 1次編集画面には、セグメントごとに既存の凍結版一覧(clipkey・作成日・切り抜き本数)へのリンク
  を出す。1次編集を変更した後でも古い切り抜き編集画面にはここから到達できる。

## 動画生成設計

- 生成スクリプト `scripts/make_clip_video.py <ID> --clipkey <key> --seg <n> --out <path> --size <WxH>`
  (パス明示 D-21。web からもコマンド単体でも同じ入口)。
- ffmpeg 一発の合成: 背景動画を `-stream_loop -1` でループ+尺で切り、`scale`+`crop` で対象
  規格へ → 字幕(ASS。libass の `fontsdir` にフォント置き場を渡す)とタイトル(同じ ASS の別
  レイヤー・全編表示)を焼き込み → 音声は凍結音源から `-ss/-t` で該当区間。
- スタイルは `config/clip_styles.json` にデータとして持つ(タイトルスタイル複数パターン・
  字幕スタイル・サイズ規格プリセット)。コードにスタイル値を埋め込まない(パターンを増やすときは
  データ追加だけで済ませる — オーナー指示)。
- 進捗・完了は既存の render_status と同型(進捗ファイル+ポーリング)。

## 資産の置き場

```
podcast/assets/fonts/               字幕・タイトル用フォント(選択肢はこのフォルダの中身)
podcast/assets/clip_backgrounds/    背景動画テンプレート(選択肢はこのフォルダの中身)
```
いずれも git 外(.gitignore に追記)。理由: フォントは数十 MB になり、ライセンス上リポジトリ
配布できないフォント(ヒラギノ等)がありうるため。→ ただしこの扱いは未決事項1(生成の実行場所)の
裁定に従って確定する。

## 調査(実装時に最新を Web で確認してから確定する。以下は現時点の想定デフォルト)

- サイズ規格プリセット(初期状態で全部チェック ON):
  - `1080x1920`(9:16 縦長 — Instagram リール/ストーリーズ・TikTok・YouTube Shorts 共通)
  - `1080x1080`(1:1 正方形 — X(Twitter) タイムライン・Instagram フィード)
  - (必要なら `1080x1350`(4:5 フィード)を選択肢としてだけ用意。既定 OFF)
- 縦長のセーフゾーン: 上部 約14%・下部 約20〜25%は投稿 UI(ユーザー名・いいね列・キャプション)と
  重なるため、タイトルは上から 15〜20% の帯、字幕は中央やや下(高さの 55〜70%)に置く。
- リール字幕のセオリー: 画面中央寄り・大きめ(1行 高さの 5〜8%)・太いゴシック・白字+黒縁
  (または強いシャドウ)・1〜2行・発話と同期して短い塊で出す。
- X(Twitter) 動画は 1:1 が無難(フィードでの専有面積と自動再生の相性)。長さ上限 140 秒(標準)。
